# Okooo 快照读盘（让球）

## 原则（用户原文）

- **冷静客观的分析**
- **不要单一被数据里的 score 带偏**
- **不要只根据 score 和 purchase 变化，也要根据我的基础数据有推理的过程**

## 适用数据

- 典型路径：`.okooo_snapshots/<event_id>.jsonl`
- 每行一条 JSON：`fetched_at`、`match`（含 **`raw` 基础数据**、`asian_line`）、`result`（含 `signals`、`decision_reason`、购买与模型字段）
- **时间序**以 `fetched_at` 为准；核对首尾时间戳，不要默认磁盘行序即采集序
- **盘口若随快照变化**（例如从 `-0.75` 变 `-0.5`）：分析过程里必须**单独说一句**，避免把不同盘口下的 `score` 连成一条无意义的「曲线」

## 读盘分层（先分层再下结论）

把结论拆成四层，避免把「综合分」当成唯一依据：

1. **市场原始层（基础数据）**（**`match.raw` 为主**；可辅以 `result.signals[*].reason` 里已引用的数字）  
   回答「市场在表达什么」：必发成交/指数/赔率、亚盘让球与水位的**数值与变化**、欧赔与 Kelly、外部让球与胜平负价、模型盘口深度等。**推理必须能指回具体字段或字段组合**，不能只有「score 跌了所以 flip」。

2. **综合加权层**（`result.score` 等）  
   多子信号加权后的综合倾向，用于看**强弱与方向**，不是单点下注指令；**接近 0** 通常表示模型内部也认为优势弱或正反抵消。

3. **门控购买层**（`purchase_side` / `purchase_team` / `purchase_score`）  
   低优势时常触发购买门控：`decision_reason` 里常见「原始优势较弱」「赢盘门槛」「临场 score 变化」「快照趋势」等对 `purchase_side` 的**二次修正**。  
   **因此：`purchase_side` 不必与 `score` 的符号直觉一致；不能用 `score` 替代本层。**

4. **模型态度层**（`model_recommendation`、`lean`、`confidence`、`model_confidence`）  
   - `model_recommendation == "观望"`：表示**不宜把该方向当成强信号**；若 `purchase_side` 仍是「上盘/下盘」，那是门控在弱优势下**硬选边**，不等于高把握。  
   - `purchase_side == "观望"`（若出现）：表示**模型明确不买、不站队**。  
   - 同时存在多列置信度时：**是否与「观望/阈值」一致**比「挑更高的数字」更重要；避免用单项高分自我安慰。

## 分析过程（对用户回复时必须按此顺序写）

回答里**先写过程、再写白话结论**（白话结论须含 **最终建议**，见下文第 4 点），过程要能让读者跟上推理链。**禁止**用「`score` 从 A 变 B、`purchase` 从 X 变 Y」作为过程的主体；它们只能作为**辅助句**，主体必须是 **基础数据 + signals + 门控** 的因果链。

### 1. 锁定场次与盘口

- 从首条或任一条读取：`home` / `away`、`result.upper_team` / `lower_team`（若存在）、`match.asian_line` / `result.asian_line`
- 若多条盘口不一致：列出**变化次数**与**最后一条盘口**，后续结论一律注明「在某某盘口下」

### 2. 拉时间线（表格一小段即可）

按 `fetched_at` 从早到晚，每条至少列：

- `model_recommendation`
- `purchase_side`（或 `recommendation`）
- `score`（仅作参考列，不作唯一判决）
- 可选：`purchase_score`（若与 `score` 分离则说明门控已介入）

读完回答两句：**购买方向是否稳定**；**模型是否长期观望**（可与第 3 步合并一句，但表格仍须保留）。

### 3. 从基础数据（`match.raw`）推理（必填，不可省略）

本步是**推理主干**，须结合**至少一条快照**写清「场上资金与报价长什么样」；若做跨快照对比，须写清**哪些 raw 字段**从早到晚怎么变。

- **最低要求**：至少引用 **2 个不同维度** 的基础字段族（下面各算一类），并说明**对上盘/下盘的含义**（用队名，不用只写上下盘代号）：  
  - **必发**：`BfIndexHome` / `BfIndexAway`、`BfAmount*`、`BfOdds*`、`BfPayout*`（热度、价、盈亏压力）  
  - **欧赔 / Kelly**：`EuroAvrHome` / `Draw` / `Away`，`Kelly*`  
  - **亚盘**：`AsianAvrLet`（应与展示盘口一致）、`AsianAvrHome`、`AsianAvrAway`；若有 `_okooo_handicap_line_samples` 可写主流样本是否集中在某一让球  
  - **隐含概率 / 离散指数**：`_okooo_euro_prob_*`、`_okooo_probability_*`、`_okooo_popularity_*`、`PolyIndex*`  
  - **外部参考**：`ExternalSpreadLowerPrice` / `UpperPrice`、`ExternalH2hUpperPrice` / `LowerPrice`  
  - **模型与深度**：`ModelFairLineDepth`、`ModelPowerEdge`（与让球是否「深/浅」相关）  
  - **提示类**（仅作旁证）：`_okooo_zhishu_tips`、`_okooo_chayi_tips`；**`_okooo_lottery_handicap` 与 `asian_line` 可能不一致**，若同时出现须在过程里点名，避免把竞彩让球与亚盘混为一谈

- **写法示例（结构而非套话）**：「必发 `BfIndexHome` 长期 80+、`BfOddsHome` 约 1.6，说明钱仍堆在瑞士胜；同时 `AsianAvrHome` 从约 1.91 抬到约 1.99，上盘水位走高 → 让球上盘赔率变差，和热度形成背离。」

- **禁止**：整段只描述 `score`/`purchase_side` 变化却**不点名任何 `raw` 字段**；或用「基础数据支持」等空话而不给字段名与方向。

### 4. 读 `signals` 并与基础数据对照

不必逐条抄全文；抓 **权重高** 且 `available: true` 的项（常见：必发指数、亚盘水位、市场平衡/背离、平局风险、赢盘门槛、快照趋势、临场 score 变化），写清：

- **谁挺上盘**、**谁压上盘或挺下盘**
- **一句话定性矛盾**（例如「钱在主队，亚盘对主队升水 → 让球上盘不舒服」）
- **能对照则对照**：若某条 `signal.reason` 里的数字与 `match.raw` 一致或明显同源，写明「与 raw 中某某字段一致」；若 reason 引用明细而 raw 无该粒度，写「该项依赖成交明细，raw 仅能看到汇总字段」即可。

### 5. 读门控在干什么（`decision_reason`）

至少概括一次：**为什么某条里 `score` 与 `purchase_side` 看起来不一致**（例如「原始分弱 + 临场下跌 + 快照修正 → 门控改买下盘」）。没有门控关键词则写「无额外门控描述，购买与综合分一致」。

### 6. 再回头看 `score` / `purchase` 变化（仅作辅助）

只用于回答：**综合分是否贴 0**、**门控是否频繁介入**（`purchase_score` 与 `score` 是否长期分离）；**禁止**用「曲线形态」替代第 3 步的基础数据推理。

## 结论写法（必须让人一眼懂）

在分析过程之后，**必须用单独小节**给出下面格式；用词口语、指队名、指上下盘，**避免「视情况而定」「存在张力」「不宜过度解读」等空泛句**。

### 固定格式：`## 白话结论`（或同级醒目标题）

1. **基础面一句 + 跟快照最后一刻买哪边（让球）**  
   - 第一句：用 **`match.raw` 事实**压缩成口语（必发/亚盘/欧赔或概率里**至少两点**，不写一堆小数也可，但要有队名与方向，例如「钱仍在瑞士，但瑞士让球上盘水位变贵」）。  
   - 第二句：「按最后一条：**买……**（队名 + 上/下盘 + 盘口，如波黑 +1 / 瑞士 -1）。」  
   - 若最后一条 `purchase_side` 为 `观望`：第二句写「**最后一条不让买，没有站队边。**」

2. **模型认不认**  
   二选一说清楚：「模型最后写的是**上盘/下盘**，算认这个方向」或「模型写的是**观望**，**不认强信号**，即使有一条 purchase 指了某边也别当稳赢。」

3. **稳不稳（看整条时间线）**  
   三选一，必须选边表述：  
   - **稳**：全程 `purchase_side` 与 `model_recommendation` 基本同向、少观望  
   - **飘**：上/下盘来回切，或长期观望里偶尔指一边 → 写「**信号飘，只能参考最后一条，别当稳的。**」  
   - **中间曾不让买**：若曾出现 `purchase_side == "观望"` 或多条 `model_recommendation` 观望 → 写「**中间系统觉得没优势、不让买或长期观望，最后又改口了，心里要打折。**」

4. **最终建议（可执行的一句/一小段）**  
   在 1–3 写完后**必须**补一节 **`最终建议`**（可放在 `## 白话结论` 内作为第 4 条，或紧跟其后的 `### 最终建议`），让读者知道「若只能选一个动作该怎么办」。要求：  
   - **承接第 3 点的稳定性**：**稳**时可写「按最后一条方向正常参考仓位」；**飘**或**中间曾不让买**时，必须明确写**轻仓跟最后一条**或**不下、仅作参考**二选一（或分句写清两种人设：必须下单 vs 不接受翻边）。  
   - **默认分档**：用户未写明极端保守或极端激进时，`最终建议`可**默认采用**下文「**`能承担一定风险且理智的投资者`默认写法**」的**方向 + 仓位折价 + 收口句**三元结构，避免只写「轻仓」却无折价口径。  
   - **与第 1 点一致**：若最后一条为「买某边」，建议里要点名**队名 + 上/下盘 + 最后一条盘口**；若最后一条 `purchase_side == "观望"`，建议里写**不参与/不下**，勿再虚构站队。  
   - **禁止**：与 1–3 矛盾的口头站队；脱离时间线的「建议综合考虑」「自行判断」等零信息句单独成段（可一句带过「自行风控」作边界，但**不能替代**具体动作）。  
   - **边界**：本 skill 不提供投注与法律建议；「最终建议」仅表示**在已给出的读盘结论下**如何对待**最后一条快照**与**整条时间线的可靠度**，用词仍须口语、可执行。

### 最终建议：`能承担一定风险且理智的投资者`默认写法（最大化「风险调整后」的可执行性）

当用户未指定风险偏好、或明确属于「要回报但要理智」一类时，**优先用本小节的三元结构**写 `最终建议`（可与上条第 4 点合并成一段，不必重复全文）：

1. **方向（只认一条）**  
   - 若最后一条 **`purchase_side` 非观望**：方向**只认最后一条**——**队名 + 上/下盘 + 盘口**（与第 1 点一致）。  
   - 若最后一条为 **观望**：**不下、不站队**；勿再写「轻仓跟某边」。

2. **仓位（与第 3 点「稳 / 飘 / 中间曾不让买」硬挂钩）**  
   - **稳**（全程基本同向、无观望）：可写 **「按你平时跟模型的常规仓位参考」** 或略低配一句即可，**不写死比例**亦可。  
   - **飘** 或 **中间曾不让买**：在「轻仓」之外**必须给出一个可操作的折价口径**，默认推荐表述为：  
     - **约为你愿意跟模型时的 ½～⅓ 档**（或等价说法：**半凯利 / 三分之一凯利** 式折价）；  
     - 并写明 **不加杠杆、不因「最后一条回来了」就滚雪球加仓**。  
   - **为什么不是满仓**：满仓等于忽略「观望/拉闸」与深盘门槛类叙述，**不叫理智下的期望最大化**。  
   - **为什么不是绝对不下**：在「能承受风险」且多数快照与 `match.raw` 仍指向同侧时，**完全不下**等于把已写进推理链的边际信息全扔光；**打折跟**才是「承认模型会怂一次」后的折中。

3. **一句收口（可选但推荐）**  
   用一句口语收束：**「方向跟最后一条；不稳就打半档～三分之一档，不加仓。」**（若最后一条观望则改为：**「不下，只当监控记录。」**）

> **说明**：此处「凯利」仅作**仓位折价的比喻**，不要求用户会算凯利公式；**不得**暗示保证收益或赛果预测。

### 禁止单独当结论的表述

- 只报一个 `score` 数字、或只描述 `score`/`purchase` 走势、**不提 `match.raw`**  
- 「建议综合考虑」「需结合临场」等无信息增量的套话  
- 不把 **队名 + 上/下盘 + 盘口** 写进「买哪边」那句（应与基础面句分开或同段内写全）  
- **`## 白话结论` 缺少「最终建议」**，或最终建议**未承接第 3 点**（稳/飘/中间不让买）却给出满仓位式语气  
- **飘**或**中间曾不让买**时，`最终建议`只写「轻仓」却**不写清折价口径**（应默认写出 **½～⅓ 档** 或 **半凯利 / 三分之一凯利** 式折价，并写**不加杠杆、不滚雪球加仓**）

## 常见误读（刻意纠偏）

- **只看最后一条 `score` 符号**：门控后 `purchase_side` 可能与 `score` 不同向，或 `score` 贴 0；叙述以 **`match.raw` + `purchase_side` + `model_recommendation` + 稳定性** 为主。
- **把 `signals` 当唯一事实**：signals 是模型加工后的摘要；**必须与 `match.raw` 交叉**，避免「复述 summary 当推理」。
- **把某一列 `confidence` 高等同于可下注**：若模型侧为观望或 `model_confidence` 很低，高 `confidence` 可能主要反映**数据覆盖/完整度**，不等于押注把握。
- **忽略盘口语义**：一球盘附近「胜平负热度」与「能否穿盘」可分离；必须结合 raw 里的平局概率/水位与 `signals` 里门槛类叙述。

## 与 CLI 的一致性（边界）

若需要与仓库内 `okooo_ah_cli.py`（或同实现）**逐字段数值一致**，以**本地执行同一版本 CLI**为准；仅凭 JSONL 对话解读属于**解释型读盘**，不声称与运行时每一步门控数值完全一致。
